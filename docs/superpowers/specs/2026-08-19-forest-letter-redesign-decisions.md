# "숲의 편지" 리디자인 — 결정 기록

- 설계서: `2026-08-19-forest-letter-redesign-design.md`
- 구현 계획: `../plans/2026-08-19-forest-letter-redesign.md`
- 범위: 41커밋, 97파일, 21개 태스크 (2026-08-19 ~ 08-20)

실행 중 사용자 확인 없이 내린 판단 22건과 그 근거를 남긴다. 각 항목은 "왜 그렇게 했는가"와 "틀렸다면 무엇을 잃는가"를 함께 적었다. 되돌릴 때는 비용란을 먼저 보면 된다.

## 설계 의도에 관한 판단

**1. 히어로 CTA를 서명 직행으로 바꾸지 않았다.** 계획서는 히어로 버튼을 `/petition` 링크로 전환하려 했으나 철회하고, 기존 스크롤 버튼과 문안("이야기 보기 ↓")을 그대로 두었다. 근거: (a) `EditableLink` 안에 `EditableText`를 중첩하면 관리자 편집 모드에서 편집 어포던스가 겹칠 위험이 있고 기존 코드에 선례가 없다, (b) 스크롤→이야기 흐름은 기존 GA4 퍼널의 전제이고, 이를 서명 직행으로 바꾸는 것은 디자인이 아니라 전환 설계 변경이다. **비용:** 히어로에서 서명까지 클릭 1회가 더 필요.

**2. 히어로 버튼을 감빛에서 아웃라인으로 되돌렸다.** 위 판단으로 이 버튼이 서명으로 가지 않게 되면서 액션 컬러를 쓸 근거가 사라졌다. 설계서 §3.1의 color diet("감빛 = 서명 CTA 단독")가 §4-1의 "히어로에 감빛 버튼 1개"보다 근본 규칙이고, §4-1은 히어로 CTA가 서명으로 간다는 전제에서 쓰인 문장이다. 결과적으로 첫 화면의 감빛은 내비의 "함께하기" 버튼 하나만 남는다. **비용:** 히어로 버튼의 시선 유인 약화(클래스 한 단어로 복구 가능).

**3. 사진 위 색 강조를 포기했다.** 내비의 공연 링크를 숲색으로 강조하려 했으나, 실측 결과 대비 4.5:1을 만족하는 값은 흰색과 구별되지 않았다. 색 선택 실패가 아니라 사진 위 유채색 텍스트의 구조적 한계로 판단해 요구 자체를 철회하고, 만들었던 `--color-forest-on-photo` 토큰도 삭제했다. 스크롤 후 상태와 모바일 메뉴에서만 숲색 강조를 유지한다. **비용:** 첫 화면에서 공연 링크가 덜 띔.

**4. 내비 "8·1 공연" 링크를 감빛에서 숲색으로 옮겼다.** 같은 바 안에서 "함께하기" 서명 버튼과 감빛이 경합해 주 행동의 힘을 나눠 가졌다. 링크·문안은 콘텐츠 결정이라 손대지 않고 색만 옮겼다. **비용:** 기간 한정 이벤트 링크의 주목도 하락. (주의: 당시 공연일이 지난 상태였다는 점이 판단에 반영됐다. 새 행사가 생기면 이 규칙을 재검토할 것.)

**5. 갤러리 "사진 제보하기" CTA를 감빛에서 숲색으로 옮겼다.** 캠페인 도메인으로 가지만, 사이트의 진짜 서명·후원 CTA는 전부 `campaigns.do/campaigns/1328` 경로를 쓰고 이것만 루트 도메인인 유일 예외다. 라벨도 사진 제보이지 서명·후원·공유가 아니다. `defaultHref`는 콘텐츠 동결이라 그대로. **비용:** 버튼 주목도 하락(채운 초록이라 여전히 뚜렷).

**6. 뉴스 카테고리 배지의 무지개 색상을 없앴다.** 배지 텍스트가 카테고리를 그대로 명시하므로 정보 손실은 없고 중복된 색 단서만 사라진다. 집회 카테고리가 감빛이던 위반도 함께 해소. **비용:** 목록에서 카테고리 구분이 색으로 즉시 안 보임.

**7. 주민 요구 인용문 아래 손글씨 서명을 만들지 않았다.** 계획서 스케치는 서명을 암시했으나 실제 서명자 텍스트가 없다. 콘텐츠 동결 하에서 지어내는 것은 사실 위조에 해당한다.

## 범위에 관한 판단

**8. `/concert` 본문은 이번 브랜치에서 이주하지 않았다.** 공연 페이지는 포스터 정체성(다크·네온·굵은 고딕)이라 종이 팔레트로 옮기는 것이 개선인지 훼손인지는 디자인 정체성 결정이며 기술적 결함 수정이 아니다. Task 19 지시에서 "타입과 팔레트를 그대로 두라"고 명시했으나 이를 번호 붙은 판단으로 기록하지 않았고, 최종 게이트 검사도 `app/concert`를 감빛 감사에서까지 제외해 예외가 조용히 넓어졌다(최종 리뷰가 지적). **현재 상태: 새 히어로 + 구 본문. 미결 항목으로 남긴다.**

**9. 카드뉴스 아트워크는 예외로 확정했다.** `card-news/cards/*`는 다운로드용 독립 그래픽으로 자체 시각 언어를 갖는다. 주변 크롬만 이주하고 카드 자체는 건드리지 않았다.

**10. `/admin`은 범위 밖으로 유지했다.** 별도 토큰 체계(`--color-admin-*`)를 쓰고 이번 리디자인 대상이 아니며, 전 태스크 제약에서 일관되게 제외했다. 감빛 12곳이 남아 있다. **비용:** 관리자 화면만 다른 색 규칙(의도된 분리).

**11. 영문판 콘텐츠 격차 6곳은 손대지 않았다.** 사진, 교통 안내 콜아웃, 정기후원·연락 섹션, 서명 이유 섹션, 인용 표기 블록이 영문에만 없다. 선존 콘텐츠 갭이고 신규 문안이 필요해 시각 리디자인 범위 밖.

## 계획서 자체 오류의 자기 수정

**12. 푸터 능선의 배경색을 제거했다.** 크림 배경을 넣으면 홈에서 깊은 초록(통계) → 크림 띠 → 깊은 초록(푸터)로 크림 슬라이버가 생긴다. 투명이어야 두 경우 모두 옳다. 계획서의 "의도된 연결" 주석은 오판이었다.

**13. 갤러리 기울임 산식을 정정했다.** "3장 중 1장만"이라 써놓고 식은 2/3를 기울이는 모순이었다. `i % 6 === 1 / === 4`로 고쳤다. 구현자가 원문을 축자 전사한 것이 옳았다.

**14. 미배정 공유 컴포넌트 2개를 찾아 배정했다.** `UtilityHeader.tsx`(404·개인정보·뉴스 상세·보도자료가 공유하는 페이지 타이틀)와 `CustomSectionsHost.tsx`(전 페이지의 관리자 커스텀 섹션)가 어느 태스크에도 없었다. 특정 페이지에 속하지 않아 페이지 단위 검증에 절대 잡히지 않는 위치였다.

**15. `/press` 하위 라우트 누락을 보강했다.** `release/`·`factsheet/`를 파일 목록에서 빠뜨려 감빛 3곳이 남아 있었다.

**16. 서명 폼의 실제 위치를 놓쳤던 것을 보강했다.** 폼 필드와 제출 버튼이 지정한 파일이 아니라 `home/inline-signature/` 하위에 있어, 홈의 주 전환 버튼이 디자인 시스템을 타지 않고 있었다.

**17. 영문 갤러리 캡션 서체를 고쳤다.** 공유 `GalleryPhotoCard`가 캡션을 한글 손글씨체로 그려 영문 캡션이 라틴 지원이 부실한 폰트로 나왔다. `latinCaptions` 옵션 prop으로 영문에서만 세리프 이탤릭으로 전환. 원인은 검사 범위를 편집 대상 디렉터리로만 한정한 것 — 규칙이 공유 컴포넌트의 출력에 관한 것이면 전체를 훑어야 한다.

## 검증 체계에 관한 판단

**18. 최종 게이트에 제목 서체 감사와 감빛 감사를 추가했다.** 초기 게이트는 유리 재질만 검사해 제목 규칙 이탈과 감빛 오용을 원천적으로 잡을 수 없었다. 감빛 오용은 6개 태스크에서 반복 적발됐다. 수동으로 계속 잡는 대신 게이트를 키웠다.

**19. `prefers-reduced-motion` 실동작 검증은 정적 검증으로 대체했다.** 라이브 에뮬레이션 도구가 없어 CSS 규칙 스코프 확인 + 주입 검증으로 갈음했다. **비용:** 실제 OS 설정에서의 동작 미확인.

**20. 낡아진 가드 스크립트를 코드가 아니라 가드 쪽에서 고쳤다.** `news-list:refactor:check`가 리디자인이 의도적으로 폐기한 카테고리 색상 상수의 존재를 요구했다. 죽은 상수를 되살려 주장을 만족시키는 것보다 낡은 주장을 고치는 쪽이 옳다.

**21. 타임라인 카드 간격 차이를 인정했다.** 참조 구현의 `space-y-12` 대신 `space-y-8/10`을 쓴 것은 27개 항목 밀도를 고려한 정당한 선택.

**22. 갤러리 기울임의 섹션 경계 리셋을 수용했다.** 실제 규칙인 1/3 비율은 페이지 전체에서 정확하고 섹션 내 교대도 정상이다. 경계 리셋은 미세한 시각 뉘앙스.

## 미결 항목 (후속 작업 후보)

우선순위 순.

1. **`globals.css`의 `@layer` 부재** — 커스텀 클래스가 Tailwind 레이어 밖이라 유틸리티가 조용히 무력화된다. 작업 중 6회 물렸고 `!` 수식자로 개별 대응했다. 근본 수정은 `@layer components` 래핑이지만 캐스케이드가 뒤집혀 지금까지 유틸리티가 지고 있던 모든 지점이 이기기 시작한다. **CSS 편집이 아니라 26개 라우트 전체 재검증이 비용이다.** 스크린샷 예산이 있는 다음 브랜치의 첫 작업으로.
2. **`/concert` 본문 이주 여부 결정** — 위 8번 참조.
3. **`.letter-btn--outline`의 밝은 배경 변형 부재** — 텍스트 색이 거의 흰색으로 하드코딩돼 크림 카드 위에서 쓸 수 없다. `PetitionSuccess`의 "URL 복사" 버튼이 이 때문에 임시 클래스로 남아 있다.
4. **`/en/donate`가 공유 `Donate*Section` 대신 인라인 구현** — 향후 수정 시 한/영 드리프트 위험.
5. **선존 가드 실패 2건** — `home-page:refactor:check`(`page.tsx`를 검사하나 섹션은 `HomeClient.tsx`에 있음), `timeline-client:refactor:check`(`useInView`를 요구하나 코드는 `useReveal` 사용). 둘 다 이 리디자인 이전부터 실패 중이며 가드가 낡은 것으로 보인다.
6. **`StoryReasonsSection`의 죽은 `color`/`icon` 필드**, **타임라인 연도 필터의 `aria-pressed` 부재**, **`maruburi.css`의 라이선스 표기가 `pretendard.css`보다 얇음** — 모두 경미.
